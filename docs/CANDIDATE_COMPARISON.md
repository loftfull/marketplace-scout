## Результат

В продукте используются четыре внешних решения: Tabler и три репозитория коннекторов. Tabler поставляет готовую систему компонентов и компоновку; коннекторы поставляют полные установленные модули извлечения данных. Собственный код Scout связывает их с интерфейсом, проверяет входы, ограничивает выполнение и независимо проверяет цены.

Из 27 обнаруженных потребительских инструментов 21 подключён к разделу «Исследование товара». Остальные не потеряны без объяснения: часть применяется в поиске/изображениях, часть дублирует выбранный инструмент, поиск Avito требует неподтверждённой карты городских ID. Все 21 операции нельзя назвать проверенными на живом товаре. Подключённый инструмент, прошедшие тесты и успешный живой ответ — разные уровни доказательств.

**Новое внедрение этой итерации:** готовые compare_products Маркета и Ozon теперь имеют таблицу сравнения на компонентах Tabler. Обычная цена, цена по карте и зачёркнутая цена разнесены; показаны продавец, область рейтинга и ошибки. Общий регион ответа не выдаётся за подтверждённый регион каждой карточки. Полный ответ остаётся раскрываемым. Новый парсер площадок, новая дизайн-система и второй backend не создавались.

## 5. Стоимость, безопасность и сопровождение

Выбранное продолжение имеет малую интеграционную стоимость: без новых npm/Python зависимостей, миграции данных и смены технологий. Замена на Refine/PriceBuddy/changedetection требует новой UI/backend/data модели и дополнительного сопровождения; доказанного выигрыша для точных региональных цен нет. Разработка парсеров с нуля исключена, поскольку подходящие исходные инструменты уже найдены.

Tabler сохраняет темы, responsive wrapper и семантические заголовки таблицы. Данные вставляются текстом; ссылки/HTML источника не исполняются. Пустые, условные и ошибочные цены не становятся обычными, небезопасные числовые ID не округляются в отображении. Существующие ограничения времени/объёма, общая блокировка выполнения, редактирование персональных полей и остановка после блокировки источника сохранены. Малые MCP-проекты требуют контроля изменений перед обновлением; закрепление версии не исключает неизвестные уязвимости.

Откат: вернуть commit этой итерации, сохранив .data/.runtime, пересобрать приложение. Формат истории и API не меняется. Управляющий план и independent critic: [change-plan](change-plans/2026-10-01-candidate-comparison.md). Дальнейшее расширение имеет смысл после доступного live-доказательства, а не посредством механического добавления ещё одного дублирующего коннектора.

## 7. Продолжение: точный артикул при вызове готового коннектора

В следующей итерации исправлена фактическая граница вызова get_product. Scout передаёт полный строковый артикул вместо URL: используется существующая строгая проверка ID в upstream, поэтому неподдерживаемый длинный артикул отклоняется до HTTP, а не сокращается до чужого. Проверяются путь карточки продавца, совпадение артикула и варианта; числовые ID с потерей точности отклоняются. Поддержка длинных ID не заявляется, исходный parser не переписан, зависимостей не добавлено.

Приёмочный отчёт теперь отдельно считает ответы браузера и доступные страницы, сохраняя VERIFIED как независимый результат. Код и фикстуры: 60 Node-тестов и 4 Python-проверки адаптера, lint/typecheck/build PASS, npm audit 0; независимый критик GO (повторил 8 регрессий). План и ограничения запуска: [identity boundary](change-plans/2026-10-01-market-identity-boundary.md).

Ограничение применения: автоматическая проверка разрешений отклонила перезапуск работающего сервера. Собранное исправление пока не загружено в экземпляр на8787. Последующий живой поиск на прежнем сервере дал 3 кандидата и 0 доступных карточек/VERIFIED; это baseline, не end-to-end проверка нового исправления. [Полные данные с обозначением версии исполнения](evidence/2026-10-01-market-identity-live-baseline.json).
