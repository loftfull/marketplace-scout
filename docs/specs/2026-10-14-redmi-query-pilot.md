# Запрос ноутбука Redmi — SPEC → PLAN → TASKS → ВЕРДИКТ

**Reuse Record:** `docs/reuse/2026-10-14-redmi-query-pilot.md`

## 1. SPEC

**Проблема / результат для пользователя:** запрос «ноутбук Redmi 2026 32Гб/1Тб» сейчас нормализуется с лишним `/` и словом «Ноутбук» внутри модели. Найденная карточка использует сокращения `32G/1T`, которые текущий разбор характеристик не распознаёт. Исправить разбор и сверку семейства RedmiBook через готовые коннекторы Scout.

**Допущение:** «Redmi» с категорией «ноутбук» означает линейку RedmiBook. Модельный суффикс и процессор не заданы и не должны добавляться как обязательные фильтры.

**Пользовательские сценарии (Given / When / Then):**
1. Given пользователь вводит «Ноутбук Redmi 2026 32Гб/1Тб», When Scout разбирает запрос, Then профиль содержит Xiaomi, семейство RedmiBook, 2026, RAM 32 ГБ и SSD 1024 ГБ; CPU остаётся незаданным.
2. Given Scout отправляет поиск, When из запроса строится строка для коннекторов, Then в ней нет служебного слова «ноутбук» и одиночного слеша; 1 ТБ передаётся как `1TB`.
3. Given карточка заголовком содержит сокращения `32G/1T`, When характеристики разбираются, Then Scout получает 32 ГБ RAM и 1024 ГБ SSD.
4. Given запрошено семейство RedmiBook, When товарная карточка подтверждает RedmiBook с любым модельным суффиксом, Then семейство совпадает, а все явно заданные год, RAM и SSD сравниваются точно; чужая марка/семейство или противоречащая комплектация не проходит.
5. Given источник возвращает товар, When его карточка заблокирована или не подтверждает все запрошенные свойства, Then предложение остаётся UNVERIFIED, источник и причина видны, discovery-цена не показывается как подтверждённая.

**Критерии приёмки:**
- [x] AC1 Точный запрос даёт Xiaomi / RedmiBook family / 2026 / 32 / 1024 без CPU; прежний точный RedmiBook Pro 16 / Ultra 5 338H продолжает разбираться.
- [x] AC2 Коннекторная строка точно `Xiaomi RedmiBook 2026 32GB 1TB`; категория и разделитель не попадают в модель.
- [x] AC3 Карточный title `Redmi Book 16 2026 Ultra5-125H/32G/1T` даёт 2026 / 32 / 1024; явные противоречия по году/RAM/SSD остаются несовпадением.
- [x] AC4 Только общий профиль `RedmiBook` принимает суффикс модели семейства RedmiBook; профиль конкретной модели и чужое семейство не получают послабления.
- [x] AC5 Поиск выполняется существующими четырьмя marketplace-коннекторами; API-ANYTHING и MAXUN не подменяют/не дублируют их в этом срезе.
- [x] AC6 Живые наблюдения отдельно от verified цены; при HTTP 403, IP-блокировке или неизвестном WB регионе результат остаётся UNVERIFIED/blocked/error и не получает fabricated price.
- [x] AC7 `npm test`, scoped Biome, `npm run typecheck`, `npm run build`, high-severity npm audit, responsive UI check и сохранение актуального read-only поиска проходят; live-положительная цена не требуется для parser-среза.

**Состояния и границы:** валидный поиск, пустой/непонятный профиль, один или несколько кандидатов, заблокированный источник, неизвестный регион, карточка недоступна; read-only, без входа в аккаунты и обхода ограничений.

**Не входит:** добавление нового marketplace provider; импорт браузерных сессий; CAPTCHA/IP обход; изменение истории/схемы; изменение пользовательских городов; принятие цены без независимой карточки; добавление Ultra 5 338H или конкретного RedmiBook размера без запроса.

**Нефункциональное:** существующие Fastify/TypeScript/vanilla UI; без новых зависимостей/сетевого сервиса; те же allowlists, deadlines, locality, atomic history and redaction; UI сохраняет Tabler, light/dark, keyboard/mobile behavior.

**Открытые вопросы:** нет. Применено допущение о семействе RedmiBook из категории ноутбук; исходный пользовательский запрос не задаёт CPU или модельный суффикс.

## 2. PLAN

- Подход и почему (альтернативы одной фразой): переиспользовать текущие закреплённые marketplace MCP/browser connectors, `parseQuery`, независимую карточную проверку и UI; исправить query normalization и поддержку generic RedmiBook family только для общего профиля.
- План файлов и границ (какие модули трогаем, какие нет): `src/parse.ts`, `src/domain.ts`, `src/specs.ts`, `tests/parse.test.ts`, `public/index.html`; без изменений коннекторов, источников цен, схемы истории и UI компонентов.
- Данные и миграции (и откат): нет; локальная история сохраняет исходную запись и сериализуется текущим механизмом. Откат — revert этих файлов; история остаётся совместимой.
- Зависимости: новых нет. API-ANYTHING (MIT, `goodnight000/api-anything` main SHA `8aca25b24347ef456cda183385be5bfb646b08e4`) и MAXUN рассмотрены как готовые общие сборщики, но не выбраны: в них нет готового покрытия четырёх нужных маркетплейсов; отдельная новая интеграция не нужна для исправления этой строки.
- Риски и как проверим: family matching допускает только расширение от общего `RedmiBook` к карточному суффиксу; точные model profiles остаются exact. Проверить профиль, карточные сокращения `G/T`, противоречащие значения и чужие модели, а также lint, typecheck, build, desktop/mobile search screen и точный локальный сценарий.
- Контрольные точки (checkpoint) и откат: сначала parser regression, затем live read-only search. Rollback — `git revert` изменения этой feature, сохранить `.data/history.json`.
