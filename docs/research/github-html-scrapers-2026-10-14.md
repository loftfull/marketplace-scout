# 50 GitHub-проектов для сбора данных из HTML и браузера

**Срез:** 14 октября 2026 года. **Задача:** собрать кандидатов для поиска карточек и цен на Avito, Яндекс Маркете, Ozon и Wildberries без вызова API самих площадок.

## Как читать рейтинг

Порядок отражает практическую пригодность для этого проекта: быстрый HTTP-запрос к публичной странице и разбор HTML предпочтительнее; браузер нужен только для страниц, которые действительно требуют JavaScript. Это не рейтинг по звёздам и не результат единого бенчмарка: скорость зависит от целевого сайта, сети, лимитов запросов и способа рендеринга. Для универсальных фреймворков описание указывает типичный режим, но конкретный адаптер нужно проверить по исходникам, чтобы исключить внутренние endpoint-ы сайта.

Сбор означает чтение открытого HTML или DOM, сформированного браузером. Это не обещание доступа или полноты данных. При отказе сайта сбор должен останавливаться; в подборку не включены проекты, если известный способ работы основан именно на скрытых API маркетплейса. CAPTCHA-обход, подмена TLS/браузерного отпечатка и ротация прокси не считаются приемлемым преимуществом.

## Практический выбор для Marketplace Scout

1. **Первый кандидат на ускорение:** Crawlee + HTTP crawler + Cheerio. Запрашивать страницу поиска/карточку как HTML и брать нужные поля, если ответ содержит карточку. Это совпадает с Node/TypeScript-приложением и не требует второго технологического стека. Документация Crawlee прямо разделяет быстрый HTTP crawler для страниц без JavaScript и браузерный вариант для JS-страниц: [Crawlee HTTP crawler](https://github.com/apify/crawlee/blob/master/packages/http-crawler/README.md).
2. **Fallback только для отдельных страниц:** Playwright или Puppeteer. Запускать браузер только если HTML не содержит карточек/цен; извлекать DOM после штатного рендеринга. Для этого нужен лимит параллельности и явная очистка браузерных процессов.
3. **Независимый быстрый ориентир:** Colly (Go) или Spider (Rust). Colly документирует параллельность и ограничения домена; его throughput claim не является результатом для Avito/Ozon/WB/Маркета. [Colly](https://github.com/gocolly/colly), [Spider](https://github.com/spider-rs/spider).
4. **Готовый продукт для слежения за известной карточкой:** уже применяемый в проекте changedetection.io. Он полезен после того, как карточка найдена, но не решает discovery или подтверждение конкретного SKU/региональной цены.
5. **Не переносить по одному README:** сначала проверить URL запроса в сетевом коде, лицензию, дату актуальности, лимиты и что парсер не читает внутренний endpoint. Для цен нужно отдельно проверить название, SKU/вариант, регион, валюту, скидочные условия и timestamp.

## Известные ограничения повторного использования

- `jez500/pricebuddy` — готовый price-tracker, но лицензия репозитория содержит `GPL-3.0 WITH MODIFICATIONS` и дополнительные ограничения коммерческого использования. Считать его архитектурным ориентиром, не свободной зависимостью, пока лицензия не рассмотрена отдельно: [исходная лицензия](https://github.com/jez500/pricebuddy/blob/main/LICENSE.md).
- `browserless/browserless` — отдельный browser service с условием SSPL-1.0 либо коммерческой лицензией; для коммерческого закрытого продукта нужна отдельная лицензионная проверка: [лицензия/репозиторий](https://github.com/browserless/browserless).
- API самого crawler-сервиса (например, локальный HTTP API Firecrawl) не равен API сайта-источника. Критерий этого списка — способ чтения целевой страницы; использовать официальный или внутренний endpoint маркетплейса вместо HTML/DOM нельзя.
- Для конкретных Avito, Яндекс Маркета, Ozon и Wildberries не подтверждена одинаковая доступность HTML без браузера. Список — каталог кандидатов, не утверждение, что все четыре площадки доступны любому из них прямо сейчас.

## Источники и граница проверки

Основной каталог GitHub по теме: [web-scraping](https://github.com/topics/web-scraping). В работе проверены описания и известные ограничения ключевых проектов из верхней части списка, а для остальных приведены прямые upstream-ссылки как кандидаты на первичную проверку. Это не 50 отдельных аудитов лицензий, активности и безопасности. До включения любого кода в продукт закрепить commit/release, проверить лицензию и проследить сетевые запросы. Публичный README, число звёзд и наличие парсера сами по себе не доказывают корректную цену, отсутствие блокировок или соответствие правилам сайта.
